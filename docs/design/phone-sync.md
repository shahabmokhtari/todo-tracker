# Design: phones that sync on their own

Status: proposed. Owner of the C# side: `src/TodoTracker.Core/Vault`, `src/TodoTracker.Core/Sync`. Fixtures:
`tests/fixtures/vault/`, `tests/fixtures/sync/` (generated by `tests/TodoTracker.Core.Tests/Fixtures`).

## Goal

iPhone, iPad and Android join the same sync as the computers **without a computer running**: each phone is a sync
*device* of its own in the existing protocol ([sync.md](../sync.md)), publishing `devices/<id>.json` + `blobs/` in
`Apps/TodoTrackerSync/<library>` (OneDrive, iCloud Drive) or its `device-<id>.json` in the library's gist, and merging
three-way exactly like `SyncPlanner`. Nothing in the protocol changes; a computer can't tell a phone from another
computer.

Non-goals (for now): the server on the phone, multi-place sync ("More than one place"), version history, Obsidian.

## The decision: the phone keeps a tasks folder too

A phone's tasks today are one JSON file (`BoardCodec`, the export format). Sync works on **files and their bytes**:
an entry is `(key, path, sha256)`, merges are line merges of the markdown, and a peer that doesn't list a file it
agreed on before is *deleting* it. Rendering the board to markdown at sync time and parsing it back afterwards
can't be made safe: everything the app doesn't model (a person's frontmatter, unknown sections, wiki-link spellings,
text between steps, a CRLF file) would be dropped on the next render, and a phone that renders a task with one
different byte has "changed" it on every other device.

So each phone keeps a **private tasks folder** in its sandbox, exactly like a computer's
(`Application Support/TodoTracker/vault` on iOS, `filesDir/vault` on Android), and:

* the **files are the truth**; the board is read from them (port of `VaultBoardStore.Reload`), and a change rewrites
  only the files of the tasks it touched, through `TaskMarkdown.Render(root, ctx, previous)` with the file's last
  parsed layout (port of `VaultBoardStore.Persist`/`Plan`);
* `board.json` becomes a one-time import (below), then is set aside as `board.json.migrated`;
* sync (port of `SyncEngine`) reads a snapshot of that folder and applies plans to it, the same as on a computer.

The shared folder (iCloud Drive, OneDrive) or the gist is only the meeting place, never the tasks folder — the same
rule as on computers (sync.md: "The tasks folder itself is never moved").

### First join

1. Create the empty vault (default tabs as `VaultBoardStore.Initialize` seeds them: `config.json` with the default
   groups whose ids are `StableGuid("group|" + NAME)`, so two new vaults meet with the same tabs).
2. Sync once with nothing published yet: everything the others have comes in. (A device with no sync history counts
   its files as old, so deletes recorded elsewhere apply: `unpublished = DateTimeOffset.MinValue` in `SyncEngine`.)
3. Bring the phone's own `board.json` in **beside** what came (port of `VaultBoardStore.ImportBeside`): a top-level
   task whose id (or any of its subtasks' ids) is already there is skipped, never replaced; others go to the tab of
   the same name, else the first tab, all or nothing. Then set `board.json` aside: an earlier `board.json.migrated`
   is never replaced (this one becomes `board.json.migrated 2`).
4. Publish.

If the first pull didn't get everything (a device's file half read, contents that haven't arrived), steps 3 and 4
wait for a later join: importing against half of the others' tasks would make copies of the rest.

Importing *after* the first pull matters: a phone that used remote mode against a computer holds copies of that
computer's tasks with the same ids; importing them first would turn every one into a "(from iPhone)" copy.

## What a phone must implement

Port these exactly; the fixtures say what "exactly" means.

### 1. Vault format (`TaskMarkdown`, `VaultText`, `Frontmatter`, `VaultFiles`)

* **Parse** a task file into a `WorkItem` tree plus its layout (`ParsedTaskFile`: frontmatter blocks with raw text and
  key signatures, block ids, check characters, priority emoji, unknown hidden data, raw attachment links, leading text
  per step, trailers/preambles per section, time-line extras, section order, newline style, BOM).
  Fixture: `vault/parse.json` (`item`, `needsWrite`, `hasAppId`, `error`).
* **Render** a task with its previous layout, byte for byte. Fixture: `vault/parse.json` `rewritten` (render after
  parse, unchanged: everything the app doesn't own comes back as typed) and `vault/render.json` (every file the app
  writes for a board, including `config.json`, `state.json`, `activity.jsonl`).
* **Ids for lines without one** are `StableGuid("<path>|<seedKey>|<n>")` with the seed keys of `ParseState.NewId`
  (`root`, `<parent seed>/<title for seed>#<occurrence>`, `note|<i>|<head>`, `time|<i>|<date> <time>`,
  `attachment|<path>`, `reminder|<i>`, `…|r<i>`), and a copied task file's ids become
  `StableGuid("<path>|copy|<id>")`. Fixture: `vault/names.json` `stableIds`, and every hand-typed case in
  `vault/parse.json`.
* **Names**: `SafeName` (file stems, ≤ 80 UTF-16 units, never half a surrogate pair), `SafeFolderName` (≤ 60, no leading
  `_` `.`), `UniqueStem` (" 2", " 3"…, case-insensitive), `BlockId` (`t` + last 7 hex of the id). Fixture:
  `vault/names.json` `titles`, `blockIds`; `vault/render.json` case `names` (clashes, `_Private` → `Private`,
  `Work?` → `Work 2`, `CON` → `CON_`, NFD input → NFC file name).
* **Times**: `created`, `completed`, `archived`, reminders and hidden data are UTC with milliseconds
  (`2026-01-05T09:00:00.000Z`); `due`, `scheduled`, `planned` are local (`2026-01-07T17:00`, seconds only when not
  zero); a date alone means 17:00 (due), 09:00 (scheduled, planned), 12:00 (done). Fixture: `vault/names.json`
  `localTimes` (Europe/Berlin, with the skipped and the repeated hour); the other fixtures use a fixed UTC−05:00.

### 2. The phone's store (a slim `VaultBoardStore`)

* **Layout**: group = top folder not starting with `_` or `.`; task = `*.md` anywhere under a group folder (not
  starting with `.`, subfolders starting with `_`/`.` skipped); root files aren't tasks; `_attachments/<…>` for files.
* **`.todo-tracker/config.json`** (synced): `schemaVersion: 2`, `groups` (id, folder, color; order = tab order;
  groups whose folder is missing stay "dormant" and are written back), `labels`, `order` (top-level task ids),
  `energyPerDay`. Written with .NET's indented JSON (2 spaces, `"key": value`, nulls left out, default escaping) and a
  final `\n`. Folders not in config get `StableGuid("group|" + FOLDER.ToUpperInvariant())`; a renamed folder keeps its
  group when it holds that group's tasks; no folders at all → `Inbox`.
* **Dormant tabs keep their place.** Sync carries files, not folders: a tab whose folder is empty on one device has
  no folder on the others, where it is dormant. config.json lists the tabs with a folder in tab order, and puts each
  dormant tab right after the nearest tab that came before it in the config.json that was read and is still there
  (first when none is). So a device that has the folder and one that doesn't write the same bytes (`[Work, Home,
  Personal]` on both), they agree on config.json, and later settings changes merge against a base. (Appending dormant
  tabs at the end gave `[Work, Personal, Home]` on the phone: the two never agreed, no base was kept, and a tab or
  label removed later could come back. Making the folders of config tabs on every device would also agree, but it
  would bring back folders someone removed by hand, and still differ until it ran.) Fixture: `vault/render.json`
  `dormantTabs`.
* **`.todo-tracker/state.json`** (not synced): focus timer, `nowOrder`, `nowArrangedAt`.
* **The Now order** syncs as `.todo-tracker/order.json`, which is *not a file*: its content is the compact JSON array of
  `nowOrder` ids (`["…","…"]`); a `setOrder` op replaces `nowOrder` (ids not on the board dropped) and rewrites
  `state.json`.
* **`.todo-tracker/activity.jsonl`** (synced): append only, one compact JSON line per change
  (`{"at","itemId","kind","summary","actorKind","actor"}`), never glued onto a torn last line. Every phone change
  appends its line with its `Actor` (`user`, or `agent`/`connector`/… where that applies).
* **New task**: `<group folder>/<SafeName(title)>.md`, unique against existing `.md` *and* `.html` stems. **Title
  change: the file keeps its name.** **Move to another tab**: the file moves to the other group folder keeping its
  name and subfolder, its `.html` rich page moves with it. **Delete**: the file (and `.html`) goes to the trash.
* **Trash**: `.todo-tracker/trash/<yyyyMMdd-HHmmss> <name>` (` 2`, ` 3`… on clashes; the time is UTC, when it was
  trashed), purged 30 days after that time. **A trash entry's age is the timestamp in its name**, never the file's
  times: a move keeps the modification time, so a task last edited months ago would otherwise be purged on the next
  start. An entry whose name doesn't start with such a timestamp is never purged. Nothing sync removes is ever
  deleted outright.
* **Writes are atomic** (temp file, flushed to the disk with `fsync`, then renamed) and a change that fails part way
  is undone (the C# undo stack), whatever the failure (not only I/O errors). A new file or a move never replaces a
  file that appeared meanwhile (check and fail). One
  writer at a time inside the app (a serial queue/actor); widgets and extensions go through the app or a file
  coordinator — there's no cross-process lock file on phones.
* **After a sync applied changes**: reload, then `TaskBoard.ReleaseWaiters` (tasks waiting for one that finished or
  went come back). Reacting to *completion flips with no activity line* (`ReactToExternalEdits`: rolling a repeat,
  unlocking the next step) is what the device where the edit was typed does; v1 phones may leave it out (they have
  no editor besides the app), at the cost of a step checked in Obsidian on a computer that synced before reacting
  waiting for that computer.

### 3. Sync

**What syncs** (`VaultBoardStore.BuildSyncSnapshot`):

| Key | Path | Kind | Merged as |
| --- | --- | --- | --- |
| `t/<id as 32 hex>` | the task's `.md` | Task | lines, with task line keys |
| `h/<id as 32 hex>` | same stem `.html` | Rich | lines |
| `f/<path>` | any other file in a group or `_` folder | File | not merged: two versions → a copy |
| `config` | `.todo-tracker/config.json` | Config | JSON, objects by property, lists by `id`/`name` |
| `order` | `.todo-tracker/order.json` (virtual) | Order | JSON list |
| `activity` | `.todo-tracker/activity.jsonl` | Activity | union of lines |

Files over 50 MB, links, hidden paths, `AGENTS.md` and anything `IsSyncablePath` refuses are left out. The hash is
SHA-256 of the exact bytes, lowercase hex.

**Accepting a peer's manifest** (`SyncEngine.Valid`): device id 2–64 ASCII letters/digits; hash 64 lowercase hex;
`config`/`order`/`activity` only at their path; `t/`,`h/` keys parse as 32-hex GUIDs and paths end in `.md`/`.html`;
`f/` key equals `"f/" + path`; every path passes `IsSyncablePath` (relative, contains `/`, no `\` `:`, no `..`, no
empty segment, none starting with `.`, ending with `.`, or starting or ending with white space, no control or
Windows-invalid characters, no `CON`/`PRN`/`AUX`/`NUL`/`COM0-9`/`LPT0-9` names, not `.tmp`, no segment over 255
UTF-8 bytes (the longest name ext4, APFS and the phones take), under 400 characters;
fixture: `vault/names.json` `syncablePaths`). A missing `since` means "oldest possible".

**Fetching** (`FetchAsync`): every peer content not held locally (by hash) is downloaded, its SHA-256 checked, and
kept in the local blob cache; any missing or mismatching content means "merge this device next time" (never a
partial merge). A content that doesn't match its hash is reported in the status (so one that keeps failing is seen),
and a device publishing to a folder writes again any of its contents whose blob there doesn't match its hash.

**A task file that can't be read** (refused by the parser with no earlier good version, or not readable at all)
stops the snapshot: sync waits until it's fixed. Left out, or listed as a plain `f/` file, it would look deleted to
the other devices, which would trash their copy. A read that fails is an error, never an empty file a later save
writes over.

**Planning** (`SyncPlanner.Plan`): port as is. Fixture: `sync/planner.json` (44 cases: new, edits on one or both
sides, keyed and plain conflicts, an invalid merge kept whole as "Title (from Phone)", made on both before any sync,
attachments and rich pages changed on both, every delete/change combination, tombstones, moves on one or both
sides, case-only renames, two files trading places through "(moving <hash8>)", a move onto a file that stays,
paths taken, activity, settings, the Now order; paired `(on a)`/`(on b)` cases end with the same files on both
devices). Rules the cases pin:

* The device whose id sorts first (ordinal) wins every choice; both devices make the same one.
* Deleted on one, changed on the other: the change wins. A version some device recorded deleting isn't brought back.
* An entry the peer lacks is deleted here only if it's unchanged since the base (or exactly a deleted version).
* Merged task text must still parse (`IsValidTask` = the vault parser accepts it), else both versions are kept whole.
  **This check must accept and refuse exactly what C# does**, or the two devices plan differently.
* Ops are ordered: moves, deletes, writes, settings/order, activity.

**Text merge** (`TextMerge.Merge`, `SyncPlanner.TaskLineKeys`): port as is. Fixture: `sync/textmerge.json` (25 cases
incl. CRLF, missing final newline, empty base, keyed step merges, both logging time, frontmatter clashes, the three
conflict policies; `taskLineKeys` shows the keys per line).

**Applying** (`VaultBoardStore.ApplySyncAsync` + `Verify`): before anything is written, check every op against the
files as they are (a write's `expected` hash, `null` = must not exist; a move's target must be free unless only the
case differs; paths re-checked with `IsSyncablePath`; nothing written through a link). A mismatch means "the vault
changed while syncing": start over (up to 3 attempts). Apply in order with an undo log; deletes go to the trash.

**The engine** (`SyncEngine.SyncOnceAsync`), per sync:

1. A different place (`Identity`) than last time: forget `RemoteVersion`/`Published` (publish everything again).
2. Read the local snapshot and the remote (`ReadAsync(self, knownVersion)`; `null` = unchanged). Nothing changed on
   either side and no heartbeat due (7 days): stop.
3. Peers = the others, heard from within 180 days, sorted by id. Tombstones from all peers: `(key, hash) → latest at`.
   A version counts as deleted when a tombstone is newer than when this device got it (`since` of the entry, else
   of what it published, else `MinValue` for a device with no history, else now).
4. For each peer: validate, fetch, load its base, plan, keep both versions of each conflict in the blob cache, apply,
   re-read, record conflicts, then **next base** = `SyncPlanner.NextBase(local after applying, peer, old base)`
   (fixture: `sync/planner.json` `nextBase`), caching the content of every task/rich/config/order entry in it.
   One peer's bad data is reported and skipped, never stops the others.
5. `RemoteVersion` = the remote's version, only when every peer merged and nothing was partial.
6. Publish when the vault changed since the last publish (fingerprint of sorted `key|path|hash`), the heartbeat is
   due, or the remote doesn't have this device: tombstones = last ones younger than 180 days whose key is still gone
   + every task/rich/file entry published last time and gone now (at = now); entries sorted by key, each with
   `since` = when this device first published that exact version (else now).
7. Drop cached contents no base and no open conflict needs.

**State the phone must remember** (`SyncState`, in the app's private storage, never in the vault or the cloud), per
place and library: device id (32 hex, one per vault, shared by every place), device name, `RemoteVersion`,
`Published` fingerprint, `PublishedAt`, `RemoteIdentity`, published entries (with `since`), tombstones, one base per
peer (`key → {key, path, hash}`), the blob cache (`blobs/<ab>/<hash>`), and the status (last sync, error, devices seen,
up to 50 open conflicts with mine/theirs/base/result hashes).

**Conflicts on the phone**: the merged file already holds both versions' lines, so v1 only needs to *list* them
("Changed on both: Trip — with Laptop"). Keep mine / Keep theirs is `TextMerge` with `ConflictPolicy.First/Second`
against the kept base, allowed only while the file is still the merge `result` and the other device has synced it
(`SyncService.ResolveAsync`, `Ready`); no merge tools on phones.

### 4. Remotes

Formats, byte for byte: `sync/manifest.json` (a device file in a folder, its blob paths, and the same snapshot as a
gist bundle with base64 contents and the marker file).

| | iOS / iPadOS | Android |
| --- | --- | --- |
| **iCloud Drive** | Yes: the person picks `iCloud Drive/Apps/TodoTrackerSync` once (`UIDocumentPickerViewController` for a folder), kept as a security-scoped bookmark. | No. |
| **OneDrive** | Probably the same picker (OneDrive's Files app provider), to be tried; else Microsoft Graph as on Android. | Later, through Microsoft Graph (below). |
| **Gist** | Yes (`URLSession`). | Yes (first remote on Android). |

**A folder through the iOS file picker** (`FolderRemote` port): every read and write inside
`startAccessingSecurityScopedResource` and an `NSFileCoordinator`; contents first, the device file last, each as a
temp file + rename (`.<name>.<8 hex>.tmp`, so other devices skip it). iCloud files may not be downloaded yet: a
placeholder (`.<name>.icloud`) is a file that "hasn't arrived" — call `startDownloadingUbiquitousItem` and merge that
device next time (the engine already does this for missing contents). The version is a hash of the other devices'
file names and content hashes, as in C#. Old unused blobs are collected only when older than 7 days (a device may be
between writing contents and its list); refresh the time of blobs still in use (> 1 day old).

**A gist** (`GistRemote` port): `GET /gists?per_page=100` (up to 5 pages) to find the oldest gist described
`Todo Tracker sync: <library>` (case-insensitive) that has `todo-tracker-sync.md`; `If-None-Match` with the ETag
(304 = nothing new); files over the API's inline size come back `truncated` with a `raw_url` (fetch it, sending the
token only to `api.github.com` and `gist.githubusercontent.com`, over https; redirects are followed by hand, at most
5, https only, the host checked again at each hop before the token goes along); publish = `PATCH` of `device-<id>.json` only (or `POST`
creating the gist with the marker the first time); the new version counts as "seen" only when the gist's history
shows the version before ours is the one we read. Refuse a bundle over 9 MB with the C# message.
Sign-in: GitHub's **device flow** (an OAuth app's public client id, scope `gist`, no secret on the phone), or a pasted
token (classic with `gist`, or fine-grained with *Gists: read and write*). The token lives in the Keychain / Android
Keystore.

**OneDrive through Graph** (later, both platforms): the same layout under
`/me/drive/root:/Apps/TodoTrackerSync/<library>:` (`Files.ReadWrite`; the "App folder" scope only works if
`approot` is exactly `Apps/TodoTrackerSync`, which depends on the app registration's name and can be localized —
check before relying on it). Use `delta` on the library folder for cheap "nothing changed" checks, upload sessions
for contents over 4 MB, and keep the folder semantics (contents first, device file last, replace whole files).

### 5. When phones sync

On launch and when coming to the foreground, 5 seconds after a change, every minute while open (as computers), and in
the background when the OS allows (`BGAppRefreshTask` on iOS; WorkManager, at least 15 minutes, on Android). A sync
must be resumable: cancelled mid-way it leaves the vault whole (plans apply atomically) and the next sync starts over.

## What phones can skip

* Version history (`VaultHistory`, git), the file watcher and its settle time, the cross-process lock, `AGENTS.md`,
  Obsidian vault discovery and wiki links to files elsewhere in an Obsidian vault (`FindEmbed`), merge tools,
  "More than one place" (read-only / write-only modes), the legacy-board migration variants beyond the one above.
* Editing rich pages: `.html` files sync and move as bytes; showing them is optional.
* **Not** attachments: a phone must hold every synced file (each ≤ 50 MB). A file a phone leaves out of its manifest
  is a file it deleted, and the others would delete it too. (A later optimisation for folder remotes: list an entry
  whose content stays only in the shared `blobs/` — the blob already exists there by hash — and download it on
  demand. Not for gists, where each device's bundle carries its own contents.)

## Hard to port faithfully (and how)

Every one of these changes bytes, which changes hashes, which other devices see as edits.

1. **String equality and order.** C# compares paths, keys and hashes ordinally (UTF-16 code units) and sorts with
   `StringComparer.Ordinal`. **Swift's `String` `==`, `<` and hashing use canonical equivalence** (`"é"` NFC equals
   `"e\u{301}"` NFD), so two different files would collapse into one dictionary key. Swift: key every map by an
   ordinal wrapper (compare `Array(s.utf16)`), sort by UTF-16 units. Kotlin `String` equality/`compareTo` are already
   ordinal UTF-16. `OrdinalIgnoreCase` (the "taken paths" set, case-only renames): upper-case each code point by its
   *simple* mapping (Kotlin `Character.toUpperCase(int)`; Swift: the scalar's uppercase mapping when it is a single
   scalar, else unchanged — `ß` stays `ß`, never `SS`).
2. **Unicode case for ids.** `"group|" + folder.ToUpperInvariant()` and the hand-written-step seed's
   `ToLowerInvariant()` use simple 1:1 mappings (`ß`.upper is `ß`, `ǅ`.upper is `Ǆ`), and .NET's invariant casing
   leaves the Turkish i's alone: `İ` (U+0130) lower-cased stays `İ` (not `i`, not `i̇`), and `ı` (U+0131)
   upper-cased stays `ı`. Swift's `uppercased()/lowercased()` use full mappings, and Kotlin's
   `Character.toLowerCase(0x130)` gives `i`: use per-scalar simple mappings, except that U+0130 and U+0131 are kept
   as they are (also for `OrdinalIgnoreCase` above). Fixture: `vault/names.json` `groupIds` (`Straße`, `İstanbul`, `ǅemal`) and the `İstanbul` step in
   `vault/parse.json` (its id is derived from `/…/İstanbul trip#1`).
3. **GUID bytes.** `StableGuid` takes SHA-256's first 16 bytes, sets `bytes[7] = (b & 0x0F) | 0x80` and
   `bytes[8] = (b & 0x3F) | 0x80`, then `new Guid(bytes)` — .NET reads the first three fields **little-endian**:
   the text form is bytes `3 2 1 0 - 5 4 - 7 6 - 8 9 - 10…15`. (So the "version" nibble shown is `bytes[7]`'s high
   nibble: the `8` in `xxxxxxxx-xxxx-8xxx-…`.) Fixture: `vault/names.json` `stableIds`. GUIDs are written lowercase
   with dashes; keys use the 32-hex form.
4. **JSON escaping.** Three encoders, all byte-relevant (`vault/names.json` `strings`):
   hidden `%%{…}%%` data uses `UnsafeRelaxedJsonEscaping` (most non-ASCII BMP characters raw, but characters beyond
   U+FFFF as `🚀` surrogate escapes, and controls, U+007F, U+00A0, U+2028 escaped; `%` → `%`; `"` → `\"`),
   uppercase hex — port its exact allow-list, the fixture only samples it; YAML scalars quote
   with the same encoder unless plain-safe; `config.json`, `state.json`, activity lines, the Now order and manifests
   use the **default** encoder (all non-ASCII → `\uXXXX`, plus `"` → `"`, `'` `+` `<` `>` `&` escaped). Neither
   `JSONSerialization` nor `JSONEncoder` nor `org.json` do this; write a small JSON writer per encoder.
5. **JSON object order.** `MergeNode` keeps the winner's property order, then the loser's new ones; config output is
   indented exactly like `JsonNode.ToJsonString(WriteIndented)`. Swift dictionaries don't keep order: use an ordered
   JSON value type for config/order merging.
6. **YAML.** C# reads frontmatter with a full YAML parser (YamlDotNet) but only for *values*; the text of each
   top-level key is kept and written back raw. Port the line splitter (`Frontmatter.Parse` blocks, `TopLevelKey`)
   exactly, and use a real YAML library's **node** API for values (Yams `Node` on iOS, snakeyaml-engine `compose` on
   Android) — never typed decoding (`due: 2026-01-20` and `id: 202601051200` are strings to C#). Duplicate keys,
   unclosed flow lists and a non-mapping document are errors (`vault/parse.json` `invalid-*`, `duplicate-*`,
   `frontmatter-not-a-mapping`); make sure the library rejects duplicates (snakeyaml-engine does by default; Yams
   needs a check on the composed mapping).
7. **Regex semantics.** .NET `\s`, `\d`, `\w` and `\p{L}` are Unicode-aware. Java/Kotlin regexes need
   `Pattern.UNICODE_CHARACTER_CLASS` (`(?U)`) for `\s`/`\d`/`\w`; `NSRegularExpression` (ICU) is Unicode-aware already.
   `$` matches before a final `\n` in all three. Emoji in patterns (`📅`, `⏫`, `️?`) are surrogate pairs in .NET
   and Kotlin, scalars in Swift — fine as long as Swift works on `String` and the others on UTF-16.
8. **Lengths and character classes.** `SafeName`'s 80 and `CopyPath`'s 40 are UTF-16 units (`s.utf16.count` in Swift).
   `char.IsLetterOrDigit` in `CopyPath` (the "(from <device>)" name, which both devices must compute alike) is per
   UTF-16 unit: a character beyond U+FFFF is never a letter there. `string.Trim()` trims Unicode white space (Kotlin
   `trim()` does; Java's `String.trim()` doesn't).
9. **Local time.** `AtLocal` uses `TimeZoneInfo.GetUtcOffset(local)`: a time in the skipped hour gets the
   *standard* offset (no shift: 02:30 → 01:30Z in Berlin), a time in the repeated hour gets the *standard* offset
   (the later instant: 02:30 → 01:30Z). `java.time` picks the earlier (summer) offset for the repeated hour and shifts
   skipped times; Foundation does its own thing. Fixture: `vault/names.json` `localTimes`.
10. **Instants.** C# times carry 100 ns ticks; manifests write `2026-01-05T09:00:00.1234567+00:00` (fraction trimmed,
    offset `+00:00`), task files milliseconds `…000Z`. Tombstones compare `at > since` exactly: parse to integer
    ticks (Kotlin `Instant` is enough; Swift's `Date` is a `Double` and loses the last digits — keep an `Int64` of
    ticks alongside).
11. **Line endings and BOM.** Files are UTF-8 without BOM, LF, ending in `\n`. A file read with CRLF or a BOM is
    written back the same way (`ParsedTaskFile.Newline`, `Bom`); merges keep each line's own ending. Never let a
    platform text API translate newlines; read and write bytes.
12. **File names on disk.** Paths in manifests are exactly what the other device sent; never normalize them (APFS
    keeps the spelling it's given; iCloud may hand back NFD names from old HFS+ Macs — compare against the manifest's
    spelling, not a normalized one). Names the phone makes come from `SafeName`, which normalizes the title to NFC.
    **Foundation decomposes file names on Apple systems:** `FileManager` (`createFile`, `createDirectory`, `moveItem`),
    `Data.write(to:)` and `String.write(toFile:)` pass a path through its "file system representation", which is NFD,
    so `Café.md` is written as `Cafe\u{301}.md` and every other device sees a different path (and hash key). Create
    folders, write files and rename with POSIX calls (`mkdir`, `open`/`write`, `rename` with the Swift string's UTF-8
    bytes) to keep the exact bytes; reading and listing (`contentsOfDirectory`, `readdir`) return what is stored, and
    APFS looks names up normalization-insensitively. The Swift store does this in `VaultFiles` (`makeDirectories`,
    `writeFile`, `writeAtomic`, `move`).
13. **Ordering in general.** Wherever C# orders (`OrderBy(... Ordinal)`, `Union`/`Concat` order, dictionary
    insertion order for `files` in the planner), the port must produce the same order: op order and copy names
    depend on it. Use insertion-ordered maps (`LinkedHashMap`, Swift arrays of pairs).

## C# changes made for this

* `VaultFiles.SafeName` no longer cuts a title between the two halves of a surrogate pair (it produced file names
  no file system or phone can hold).
* `IsSyncablePath` refuses control characters on every system (on macOS and Linux it accepted a tab or newline in a
  path that Windows refuses, so devices disagreed on what syncs).
* `config.json`, `state.json` and merged settings are written with `\n` on every system. .NET's indented JSON uses
  the system's line ending (`JsonSerializerOptions.NewLine`), so Windows wrote them with CRLF: different bytes from
  every Mac (and phone) for the same settings, so the devices never agreed on them. Ports: always `\n`.
* Those are the only behavior changes; everything else is fixtures and tests.
* No API was refactored: the generators drive the real store (`VaultBoardStore` with a board to import, `ReadSyncAsync`),
  `TaskMarkdown.Parse/Render`, `SyncPlanner`, `TextMerge`, `FolderRemote` and `GistRemote` (with the fake GitHub).
